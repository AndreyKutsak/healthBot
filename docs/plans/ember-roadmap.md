# EMBER — етапи розробки

Основа: [зведена концепція](../specs/ember-concept-v1.md). Цей план створено за дорученням користувача. Він визначає порядок робіт, а не починає реалізацію, платні запити, завантаження баз або публікацію.

## Релізні межі

**v1 — приватний робочий застосунок для автора:** iOS, Android, браузер; українська й англійська; харчування, рецепти, тренування, сон, форма, звички, єдиний ШІ, підсумки, керовані нагадування, офлайн-записи та п’ять типів мобільних віджетів. Бюджет API — 5 USD/місяць, достатність ще перевіряється.

Внутрішні етапи нижче — проміжні результати розробки. Наприклад, готовий облік їжі ще не означає готовий випуск v1. Погоджені функції не переносяться до наступних версій без рішення користувача.

**Після v1:** поліпшення за результатами пілоту, інтеграції гаджетів, особистий планер. Планер для двох, публічний продукт і монетизація — окремі продуктові рішення, не автоматичні зобов’язання.

## Послідовність v1

| Етап | Результат | Основні залежності |
|---|---|---|
| 0. Перевірки й рішення | Реалістична архітектура, джерела їжі, перевірка бюджету й обмежень ОС | Концепція та дозвіл на відповідні роботи |
| 1. Сценарії й дизайн | Перевірені швидкі потоки, видимі КБЖВ, теми, адаптація до екранів | 0; наявний схвалений візуальний напрям |
| 2. Основа продукту | Обліковий запис, модель даних, три клієнти, мови, чернетки й синхронізація | 0; основні рішення 1 |
| 3. Харчування та рецепти | Надійний облік, повтори, приготування, база продуктів | 2; джерела з 0 |
| 4. ШІ в реальних сценаріях | Єдиний помічник, розбір тексту/фото/диктування, підтвердження, пам’ять, бюджет | 2–3; архітектура ШІ з 0 |
| 5. Тренування | Програми, фактичні підходи, адаптації після підтвердження | 2, 4 |
| 6. Сон, форма, стан і звички | Спільний особистий контекст і оцінка витрат енергії | 2, 4; формули з 0 |
| 7. Підсумки й нагадування | Корисний зворотний зв’язок без зайвих сповіщень | 3–6 |
| 8. Віджети | П’ять типів на iOS та Android із доступними для ОС діями | 0, 2, 3, 5–7 |
| 9. Наскрізна перевірка | Стабільність, приватність, доступність, офлайн та швидкість | Усі функціональні етапи |
| 10. Особистий пілот | Два тижні реального користування та рішення щодо готовності v1 | 9 |

Перевірки віджетів, сповіщень, сну та офлайн починаються на етапі 0: їхні обмеження мають вплинути на архітектуру завчасно. Захист даних, локалізація та перевірки входять у кожен етап; етап 9 перевіряє їх разом.

## Як вести роботу

- Детальний [тудулист v1](ember-v1-todo.md).
- Окремий [список наступних версій](ember-next-versions.md).
- `[ ]` — не завершено. `[x]` — виконано й перевірено; під задачею додати короткий доказ: перевірка, файл, запис демонстрації або результат пілоту.
- Для розпочатої задачі додати виконавця та статус «у роботі». Для блокованої — причину й залежність. Саме написання коду не означає готовність задачі.
- На завершення етапу показати користувачу результат, перевірки та відомі обмеження. Нові вимоги й перенесення погодженого обсягу обговорюються окремо.
- Календарні оцінки встановлюються після етапу 0 з урахуванням виконавців і доступного часу. Зараз строки не обіцяються.

## Умова завершення v1

Усі обов’язкові задачі v1 та критерії концепції перевірені на цільових платформах; особистий пілот завершений; немає відомих блокувальних втрат/дублів даних, порушень приватності чи непогоджених змін планів і витрат. Результати пілоту розглянуті разом із користувачем. Публічна публікація в магазинах або відкриття реєстрації не є умовою приватного v1 і не запускається автоматично.
