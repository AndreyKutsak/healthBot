# EMBER — джерела харчових даних

Дослідження документації для V1-005. Користувач погодив підхід 02.11.2026: USDA для звичайних продуктів, OFF умовно після перевірки ліцензії та покриття, приватний каталог і дозволені офіційні ресторанні дані. Бази не завантажувалися, облікові записи не створювалися, платні запити не виконувалися. Фактичне покриття українських товарів не виміряне; погодження підходу не закриває перевірок і не запускає імпорт.

## Висновок і пропозиція

Для v1 пропонується кілька джерел із видимим походженням: USDA для звичайних продуктів; Open Food Facts як кандидат для упакованих товарів після перевірки ліцензійної моделі; особисті продукти з підтверджених користувачем етикеток; ресторанні дані з офіційних джерел, якщо дозволене їх використання. Невідомі страви — явно позначені оцінки, які користувач підтверджує.

Єдиного джерела з перевіреним повним покриттям України та місцевих ресторанів у межах цього дослідження не встановлено. Перелік країн постачальника не доводить повноту каталогу.

## Порівняння

| Джерело | Перевірене | Роль і обмеження для EMBER |
|---|---|---|
| USDA FoodData Central | Дані CC0; CSV/JSON для завантаження, API з ключем | Основа для звичайних інгредієнтів. Потрібні українські назви/синоніми та точний вибір сирого або готового продукту. Не заміна конкретній українській марці |
| Open Food Facts | База ODbL, зображення CC BY-SA; API та масові експорти | Кандидат для упакованих товарів. Українське покриття й повнота КБЖВ ще не перевірені. Умови похідної/об’єднаної бази потрібно визначити до інтеграції |
| FatSecret | Україна й українська мова є у списку локалізації; безкоштовні редакції обмежені США | Комерційна альтернатива. Ціна українського доступу та права на потрібне зберігання вимагають окремих умов. Не закладається у v1 без погодження витрат |
| Офіційні ресторани | McDonald’s Україна має калькулятор, KFC Україна — файл харчової цінності | Дані конкретної мережі/ринку. Публічна сторінка не підтверджує дозвіл на масове копіювання й розповсюдження |
| Власні записи | Етикетка, введення користувача, підтверджений рецепт | Приватний довідник; зручний повтор і виправлення. Оцінка ШІ не стає перевіреним фактом через підтвердження користувачем |

Джерела перевірки:

- [USDA: API та ліцензія](https://fdc.nal.usda.gov/api-guide/), [набори для завантаження](https://fdc.nal.usda.gov/download-datasets/). API має стандартний ліміт 1000 запитів/годину/IP; для локального каталогу передбачаємо імпорт, а не API на кожну зміну грамів.
- [OFF: офіційна документація API й експортів](https://openfoodfacts.github.io/openfoodfacts-server/api/), [ліцензійні правила](https://github.com/openfoodfacts/openfoodfacts-server/blob/main/docs/api/tutorials/license-be-on-the-legal-side.md). Документація рекомендує експорти для масового використання; вони оновлюються щодня. Сторінку українського каталогу інструментом не вдалося прочитати, тому кількість товарів не наводиться.
- [FatSecret: редакції та ціни](https://platform.fatsecret.com/api-editions), [локалізація](https://platform.fatsecret.com/docs/guides/localization), [правила зберігання](https://platform.fatsecret.com/docs/guides/storable-data). Загальна документація обмежує кешування та перелічує ідентифікатори, які дозволено зберігати безстроково. Власний постійний каталог і незмінні історичні КБЖВ не можна вважати дозволеними без відповідного договору; комерційні умови слід перевірити окремо.
- [McDonald’s Україна](https://www.mcdonalds.com/ua/uk-ua/eat/nutrition_calculator.html), [KFC Україна](https://www.kfc.ua/nutritional-values). Дозвіл на імпорт цих матеріалів не підтверджено.

## Довідник продуктів і приватна БД

Погоджений PostgreSQL залишається сховищем застосунку. Харчовий довідник — джерело поживності; приватні щоденники — записи про те, що конкретна людина запланувала або з’їла. Це різні сутності.

Пропонована модель:

1. Каталоги джерел: зовнішній ID, ліцензія, країна, назва, марка, одиниця/основа розрахунку, версія, дата отримання, поживність і пропущені поля.
2. Особисті продукти/рецепти: власник, підтверджені значення, джерело й оцінка точності. Жодного автоматичного публічного внесення в OFF чи спільний каталог.
3. Щоденник: час споживання, план/факт, кількість, одиниця, знімок використаних значень і походження. Оновлення каталогу не перераховує минулі прийоми їжі.
4. На пристрої: дозволена локальна копія потрібних продуктів, власні рецепти та черга змін. Повний світовий каталог не завантажується на телефон.

Розділення каталогів потрібне для походження й контролю доступу, але саме по собі не гарантує виконання ODbL. До підключення OFF необхідно визначити, чи є результат похідною базою, які атрибуції та умови поширення застосовуються. Приватний щоденник не планується публікувати; якщо ліцензійна модель конфліктує з цим, джерело не підключаємо без нового погодження.

## Пошук, розрахунки й оновлення

- Спочатку показувати власні й нещодавні продукти, потім точні збіги марки/назви, далі звичайні аналоги. Подібні назви не означають однаковий продукт.
- До введення кількості показувати за 100 г; після — миттєвий локальний перерахунок без ШІ. Штуки й частини потребують відомої або підтвердженої маси.
- Розрізняти 100 г / 100 мл / порцію, сирий/готовий стан, сіль/натрій та визначення поживних полів джерел. Відсутня клітковина не дорівнює нулю.
- Внутрішній ID OFF може містити код товару; це не додає сканування штрихкодів до погодженого інтерфейсу.
- Оновлення імпорту проходить через проміжну перевірку: одиниці, дублікати, пропущені поля, аномальні зміни. Нова версія стає доступною для нових записів; старі знімки зберігаються.
- Перевіряти наявність нових випусків USDA; для OFF визначити частоту синхронізації після вибору обсягу. Щоденна доступність експорту не зобов’язує EMBER щодня імпортувати всю базу.
- Для ресторану зберігати мережу, країну, за потреби заклад/місто, варіант і розмір порції, дату меню. Геолокація допомагає пошуку, але не підтверджує склад або наявність страви.
- Якщо точного товару немає: запропонувати аналог, уточнення або фото етикетки. Для ресторанної страви без даних показувати оцінку з можливістю виправлення. Жодних вигаданих точних грамів.

- [ ] Визначити ліцензійну модель OFF, атрибуцію та допустиме поширення каталогу; за конфлікту повернутися до користувача з альтернативами.
- [ ] Провести вибіркову перевірку покриття: пропозиція — 30 звичайних інгредієнтів, 50 товарів українських магазинів, 20 ресторанних позицій. Це план перевірки, а не отримані результати.
- [ ] Окремо виміряти точні збіги, наявність КБЖВ/клітковини, порцій, дати й української назви. Аналог не рахувати точним збігом.
